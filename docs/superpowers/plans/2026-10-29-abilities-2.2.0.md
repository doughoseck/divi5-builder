# Abilities 2.2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Release 2.2.0 of the `divi5-builder` plugin: write abilities for the content categories and Divi, the two-step permanent delete, and a change history that holds enough to put every write back.

**Architecture:** Every write is a new definition under `plugin/divi5-builder/inc/abilities/`, added with the 2.1.0 `d5b_rc_def()` helpers and gated, audited and scrubbed by the existing run wrapper. A new `history.php` writes one row per successful write to `{prefix}d5b_history`; a new `confirm.php` issues and checks the delete confirmation codes; a new `inc/blocks.php` is the PHP port of `scripts/blocks.js` that `divi-section-edit` and `divi-text-edit` build on. The Divi writes call the named functions in `parts/page-building.php`, refactoring a route closure into a named function only where needed, byte-identical.

**Tech Stack:** PHP 7.4+ (WordPress plugin), WordPress Abilities API (6.9+), the plugin's PHP test harness (`scripts/plugin-test-stubs.php`, `scripts/plugin-*-test.php`), Node for the live script.

**Spec:** `docs/superpowers/specs/2026-10-29-abilities-2.2.0-design.md`, which extends `docs/superpowers/specs/2026-10-28-abilities-design.md`.

## Global Constraints

- Plugin version `2.2.0`; `D5B_DB_VERSION` becomes `'2'` (adds the history table; `dbDelta` on the audit table is a no-op).
- Ability names `divi5-builder/<category>-<action>`; defs through `d5b_rc_def()`; descriptions at least 40 characters; every input property described; `additionalProperties: false`; `input_schema.default = array()` is added by the wrapper.
- Write defs set `annotations`: `readonly => false`; `destructive => true` only for `*-trash`, `*-delete`, `menus-item-remove`, `divi-ds-variable-archive`; `idempotent => true` for set-style writes (`meta-set`, `media-update`, `menus-assign-location`, `divi-builder-mode`), false otherwise.
- The one rule: trash where WordPress can; otherwise preview + confirmation; full "before" in the history; `expect_hash` on every content update; a masked read is never written back.
- `expect_hash` = `md5( post_content raw )`, the same as `d5b_rc_hash()` and `wp.js`.
- New content status defaults to `draft`; `publish`, `future`, `private` only when given and `current_user_can( $type_obj->cap->publish_posts )`.
- Content containing `<!-- wp:divi/` is refused with `needs_unfiltered_html` when `! current_user_can( 'unfiltered_html' )`, on every content write path.
- Strictest switch wins by object type on every write path that touches a post-like object (`d5b_rc_type_on()`), plus the Divi category for `divi-*`.
- Error codes: `invalid_input` 400, `not_allowed` / `forbidden` 403, `not_found` 404, `stale` 409, `masked_read` 409, `confirmation_invalid` 409, `crosses_markup` 409, `ambiguous` 409, `cannot_trash` 409, `unavailable` / `history_unavailable` 503 (extend `d5b_ability_http_status()`).
- Every new PHP file goes into the loader's explicit file list in the same commit (`scripts/plugin-anysite-test.php` enforces list == disk); inc files only define functions.
- Stand-ins must behave like real WordPress; where unsure, the implementer says so in the report rather than guessing.
- No em dashes in any doc or copy; no client or site names in public files.
- Only `media-upload` fetches the internet: http/https only, no private, loopback or link-local address (checked per hop, at most 3 redirects), 20-second timeout, capped at `wp_max_upload_size()` and the site's allowed mime types.

## Review Focus

1. A page edited in the Visual Builder between the AI's read and its write: every content write must answer `stale` and leave the stored content byte-identical (Task 3 tests it for `posts-update`, Task 9 for `divi-section-edit` and `divi-text-edit`).
2. A confirmation code replayed after the term was renamed: `confirmation_invalid` with reason `stale`, nothing deleted (Task 2).
3. A `divi-text-edit` whose `old` also appears inside a CSS class or an option value: only the visible text changes (Task 9).
4. A trashed page that was `publish` and is restored: it comes back `publish`, not `draft` (Task 3).
5. `media-upload` from a URL that redirects to `http://127.0.0.1/` or an internal hostname: refused before any body is read (Task 5).

  - In register.php: `d5b_ability_audit_current_id(): int` (the audit row id of the running call, 0 outside one); `d5b_ability_run()` sets final status `ok_no_history` when the handler returned a result carrying `_history_failed => true` (handlers set it when `d5b_history_write()` returned 0; the wrapper strips the key before the response).
