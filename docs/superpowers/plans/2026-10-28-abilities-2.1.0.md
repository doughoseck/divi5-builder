# Abilities Release 2.1.0 (master switch, read-only abilities, audit log) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `divi5-builder` 2.1.0 registers read-only WordPress Abilities for every category in the design, behind a master switch that is off by default and a switch per category. Every ability call is recorded in a 30-day audit log.

**Architecture:**
- `inc/switches.php` gains the abilities part of the switch store.
- `inc/settings.php` gains the master and category switches on the existing settings page.
- A new `inc/abilities/` folder holds:
  - the category table;
  - a registration gate on WordPress's `wp_abilities_api_*` hooks;
  - a run wrapper that every ability goes through, which handles permission, audit and secret scrubbing;
  - the audit log store;
  - one file of read abilities per group.
- Nothing registers unless `wp_register_ability` exists, the master switch is on, and that category is on.

**Tech Stack:** PHP 7.4+ WordPress plugin, WordPress Abilities API (6.9+), custom table via `dbDelta`, Node 18 built-ins for the live check. PHP tests on WordPress stand-ins (`scripts/plugin-test-stubs.php`).

**Spec:** `docs/superpowers/specs/2026-10-28-abilities-design.md` (approved 2026-10-28). Releases 2.2.0 to 2.4.0 get their own plans.

## Global Constraints

- **Plugin version and floors:**
  - version `2.1.0` in the header, `D5B_VERSION`, readme.txt, SECURITY.md, and the test that pins the header
  - `Requires at least: 6.0` stays
  - abilities only when `function_exists( 'wp_register_ability' )`, never fatal without it
- **Names:**
  - abilities: `divi5-builder/<category>-<action>` (lowercase, dashes, exactly one slash)
  - category slugs: `divi5-builder-<category>` (lowercase, dashes)
- **Registration (per WordPress core `abilities-api.php`):**
  - categories on `wp_abilities_api_categories_init`, abilities on `wp_abilities_api_init`
  - args: `label`, `description`, `category`, `execute_callback`, `permission_callback` (always given; never rely on `required_capabilities` alone), `input_schema`, `output_schema`
  - `meta`: `annotations => [ 'readonly' => true, 'destructive' => false, 'idempotent' => true ]`, `public => true`, `show_in_rest => true`
- **Switch store:** the existing option `d5b_switches` (a site option on multisite), new key `abilities`:
  - shape: `{ master: { on, changed_at, changed_by }, categories: { <slug>: { on, risky_on, changed_at, changed_by } } }`
  - a missing value reads as **off** for the master and every `risky_on`
  - a missing category `on` reads as **on** (it only matters once the master is on)
  - only `inc/switches.php` and `inc/settings.php` may write it, enforced by the static scan in `plugin-switches-test.php`
- **Who flips switches:** the wp-admin form only (nonce `d5b_switches`, `d5b_settings_cap()`). Never `show_in_rest`, never an ability or a REST route.
- **Audit log:**
  - table `{$wpdb->prefix}d5b_audit`, per site on multisite
  - kept 30 days, pruned daily by WP-Cron hook `d5b_audit_prune`
  - created on activation, on the must-use first admin load, and when the stored option `d5b_db_version` differs from `D5B_DB_VERSION` = `'1'`
  - dropped by `uninstall.php`, along with `d5b_db_version`
- **Secrets never leave the site:** no `user_pass`, `user_activation_key`, application passwords, session tokens, or options outside the settings allow-list in any output.
- **Public repo:** no client, site or personal names, and no em dashes in new prose.

## Review Focus

1. **Master off, but a cached or early `wp_get_abilities()` call** still returns our abilities. Expected: nothing registered.
   - *Test:* Task 2, `master off: no divi5-builder ability and no category registered after both hooks fire`.
2. **An Editor or Contributor calling a read ability for a post they cannot read** (a draft or private post of another user). Expected: refused per object, with an audit row.
   - *Test:* Task 4, `posts-get: contributor reading another user's draft is refused and logged`.
3. **A user record or a settings read leaking secrets.** Expected: none of the secret keys appear anywhere in any output.
   - *Test:* Task 5, `secret scan: no output of any ability contains a forbidden key or value`.
4. **The audit table missing** (a must-use install that never ran the activation hook, or a failed `dbDelta`). Expected: abilities still work, the log write fails quietly with no fatal, and the next admin load creates the table.
   - *Test:* Task 3, `missing table: run still returns, no fatal, table created on next d5b_audit_maybe_install`.
5. **An error log that is huge or not where expected** (`WP_DEBUG_LOG` false or set to a custom path). Expected: only the configured debug log, last 200 lines, at most 64 KB, and a clear "no debug log" answer otherwise. Never any other path.
   - *Test:* Task 5, `error-log: missing log answers no_debug_log; huge log returns at most 200 lines and 64 KB; a path parameter is not accepted`.

### Task 2: Category table, registration gate, run wrapper

**Files:**
- Create: `plugin/divi5-builder/inc/abilities/categories.php`, `plugin/divi5-builder/inc/abilities/register.php`
- Modify: `plugin/divi5-builder/divi5-builder.php` (add files to the explicit list; hook `wp_abilities_api_categories_init` → `d5b_abilities_register_categories`, and `wp_abilities_api_init` → `d5b_abilities_register`); `scripts/plugin-anysite-test.php` (loader file list); `scripts/plugin-test-stubs.php` (append stubs for `wp_register_ability`, `wp_register_ability_category`, `doing_action`, recording calls)
- Test: `scripts/plugin-abilities-gate-test.php` (new)

**Interfaces:**
- Consumes: Task 1's `d5b_abilities_category_on()`.
- Produces:
  - `d5b_ability_categories(): array`, keyed by short slug (`posts`, `pages`, `media`, `taxonomy`, `comments`, `meta`, `cpt`, `blocks`, `menus`, `revisions`, `search`, `settings`, `templates`, `appearance`, `widgets`, `cache`, `health`, `users`, `plugins`, `themes`, `core`, `history`, `divi`). Each value is `{ label, description, wp_slug }`, where `wp_slug` = `divi5-builder-<short>`. Email has no read ability, so no category in 2.1.0.
  - `d5b_ability_defs(): array`: every ability definition from the files Tasks 4 to 6 add, as `{ name, category, label, description, input_schema, output_schema, handler, permission }`. `handler` and `permission` are callables taking `array $input`. Built by a filter-free registry: `d5b_ability_add( array $def ): void`, which each group file calls when included. Unique names are enforced.
  - `d5b_abilities_register_categories(): void`: registers only categories that are on and have at least one def.
  - `d5b_abilities_register(): void`: registers every def whose category is on, with the Global Constraints `meta`, and `execute_callback` and `permission_callback` set to the run wrapper closures below.
  - `d5b_ability_run( string $name, $input )`: returns the handler result or `WP_Error`. It:
    - scrubs secrets with `d5b_ability_scrub()` (Task 5);
    - writes one audit row through `d5b_audit_write()` (Task 3), status `ok` or the error code;
    - catches `Throwable` from the handler and returns `WP_Error( 'internal_error' )` (the message is logged, never echoed).
  - `d5b_ability_permit( string $name, $input ): bool|WP_Error`: calls the def's permission callable. A refusal writes an audit row with status `forbidden`.

- [ ] **Step 1: Write the failing tests:**

  - `one category off: none of its abilities or its category registered, others intact`
  - `no Abilities API (wp_register_ability missing): loader loads, hooks fire, nothing fatal`
  - `run wrapper: handler exception becomes internal_error, audit row written`
  - `permission refusal: false returned, audit row status forbidden`
  - `names: every def name matches ^divi5-builder/[a-z0-9]+(-[a-z0-9]+)*$`
  - `loaded twice: registration happens once`
- [ ] **Step 2: Run them.**

### Task 3: Audit log

**Files:**
- Create: `plugin/divi5-builder/inc/abilities/audit.php`
- Modify: the loader (activation and `admin_init` install, the `d5b_audit_prune` daily cron schedule on activation, cleared on deactivation); `plugin/divi5-builder/uninstall.php` (drop the table per site, delete `d5b_db_version`); `inc/settings.php` (a read-only "Audit log" list under the settings page: newest 50 rows, filter by ability and user)
- Test: `scripts/plugin-abilities-audit-test.php` (new); extend `plugin-uninstall-test.php`

**Interfaces:**
- Produces:
  - `d5b_audit_maybe_install(): void`: `dbDelta` when `get_option( 'd5b_db_version' ) !== D5B_DB_VERSION`, then sets it.
  - The table columns: `id` bigint auto-increment PK, `created_at` datetime (UTC) indexed, `user_id` bigint, `ability` varchar(191) indexed, `args` longtext (JSON, redacted, max 8 KB), `status` varchar(64), `duration_ms` int, `ip` varchar(45).
  - `d5b_audit_write( string $ability, array $args, string $status, int $duration_ms ): bool`: never throws, returns false on failure. The IP comes from `REMOTE_ADDR` only.
  - `d5b_audit_redact( array $args ): array`: values of keys matching `/pass|secret|token|key|auth|cookie|nonce/i` become `"[redacted]"`, and strings over 1024 characters are truncated with `…[truncated]`.
  - `d5b_audit_prune(): int`: deletes rows older than 30 days and returns the count.
  - `d5b_audit_list( array $filters, int $limit = 50, int $offset = 0 ): array`, used by the screen and by the History ability in Task 6.
