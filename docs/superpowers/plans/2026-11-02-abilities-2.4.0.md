# Abilities 2.4.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Release 2.4.0 of the `divi5-builder` plugin: the maintenance loop as abilities (status, keep a copy, update, check the pages, roll back) for plugins, themes and core, plus users and a test email, behind the master, category and risky switches.

**Architecture:** Every write is a `d5b_wc_def` definition using the 2.2.0 and 2.3.0 helpers (history rows, confirmation codes, secret and key rules, `risky => true`). Two new shared helpers carry the release: `d5b_pages_check()` (a PHP port of the script's page health and comparison) and `d5b_keep_copy()` (a folder copy into the history store, with the per-copy and total caps). Updates and installs go through the existing engine (`wpsu_status`, `wpsu_update`, always loaded) and core's upgraders. Nothing in the REST route or the PC script changes.

**Tech Stack:** PHP 7.4+ WordPress plugin, WordPress Abilities API (6.9+), the plugin's PHP test harness (`scripts/plugin-test-stubs.php`, `php -d max_execution_time=60`), Node for the live script.

**Spec:** `docs/superpowers/specs/2026-11-02-abilities-2.4.0-design.md` (extends the master design and the 2.2.0 and 2.3.0 designs).

## Global Constraints

- Plugin version `2.4.0`; `D5B_DB_VERSION` `'4'` (no new table; the bump drives the consent step `'3' -> '4'`, also `'1'`/`'2' -> '4'`, once per network via `d5b_abilities_consent_240`, notice text: the master "was turned off by the update to 2.4.0, which adds abilities that manage users, plugins, themes, WordPress updates and email, and whose normal writes send a test email, send password reset links, update translations and refresh the update list").
- New category `email` ("Email", "Send a test email to a site user or the admin address."); risky notes for `users`, `plugins`, `themes`, `core` verbatim from the spec's "Switches" section; `email` has no risky box.
- Normal writes (category only): `users-password-reset`, `email-send-test`, `translations-update`, `updates-check`. Every other 2.4.0 write is `risky => true`.
- Capabilities as the spec's "Abilities" section; on multisite install, update, rollback and delete of plugins and themes also need `is_super_admin()`; `email-send-test` needs `manage_options`.
- The one rule: every write has a history row; update, rollback and delete of a plugin or theme have `kept` (the copy) or were called with `without_copy: true` (row says `kept: null`); core update keeps versions only; translations keep a count.
- Self-protection: `divi5-builder/divi5-builder.php` and the legacy plugin files (`D5B_LEGACY_PLUGINS` if defined, else the four names in `inc/takeover.php`) are refused as `self` for deactivate, delete, rollback, update.
- Install download URLs must be `https://downloads.wordpress.org/...` exactly as returned by `plugins_api` / `themes_api`; anything else refused `bad_source` before the upgrader runs.
- Page checks: at most 7 pages (home, 5 most recently modified published pages, newest published post), `wp_remote_get` with `timeout => 15` and a cache-buster `?d5b=<time>`, round budget 60 s, `unavailable` when the before round fails on every page.
- Copies: per-copy cap 512 MB (`copy_too_big`), total store cap 2 GB (`store_full`), copy failure `copy_failed`; all three refuse the write unless `without_copy: true`.
- Rate limits via transients: `users-password-reset` one per user per 10 min and 20 per site per hour; `email-send-test` 5 per site per hour; `updates-check` one per 5 min; refused `too_soon`.
- No password, reset key or download token ever appears in a result, an audit row or a history row (tests assert on the JSON of all three).
- Every new PHP file in the loader's explicit list in the same commit; inc files only define functions; no function name declared in two files (the loader test from 2.3.0 covers it).
- The 2.2.0 and 2.3.0 rules apply unchanged (ASCII key rule and case check, `d5b_wc_secret_free`, `d5b_wc_core_error`, `warnings`, `ok_no_history`, risky gate re-checked in permit and run).

## Review Focus

1. A plugin whose folder name differs from its slug (`wordpress-seo/wp-seo.php`): the copy, the rollback and the delete must use the folder from the plugin file's dirname, never the slug (Task 1 keep-copy test with such a file; Task 3 rollback test).
2. Activating a plugin that fatals on load: `activate_plugin` returns a WP_Error from its sandbox, the plugin must not be left in the active list, the page checks must not run, the result is `activation_failed` (Task 2 test).
3. A rollback while WordPress has since updated the plugin further (kept 1.2, installed 1.4): the rollback restores 1.2 and the row's before holds 1.4, with a `warnings` line naming the skipped version (Task 3 test).
4. Deleting a user who owns 30,000 posts: the preview counts, the row holds 30,000 ids (about 200 KB, under the 8 MB cap), and the delete runs within the request (Task 6 test with a stub returning 30,000 ids asserts the row size and that no truncation flag is set).
5. A test email when the mailer is misconfigured: `wp_mail` returns false, `wp_mail_failed` fires with the PHPMailer message, the result has `sent: false` and `mailer_error` with the message, the history row says the same, and the rate limit still counts the attempt (Task 7 test).

### Task 1: Shared helpers: page checks, keep copy, store size, self rule, rate limit

**Files:**
- Create: `inc/abilities/maint-common.php`
- Modify: `inc/abilities/history.php` (`d5b_history_files_remove` recursive; new `d5b_history_store_bytes(): int`), loader list, stubs (`wp_remote_get` already exists; add `copy_dir`, a fake filesystem root under the test temp dir, `is_super_admin`)
- Test: `scripts/plugin-abilities-maint-test.php`

**Interfaces (produces):**
- `d5b_pages_watched(): array` of up to 7 urls (home, 5 most recently modified published pages, newest published post), each with `?d5b=<time>`.
- `d5b_pages_round( array $urls, int $budget_s = 60 ): array` of `{ url, status, bytes, closed, fatal, title, skipped }`; the FATAL regex is the script's, verbatim.
- `d5b_pages_compare( array $before, array $after ): array` of problem strings, the script's rules (a bad-before page is not blamed; worse = status not 200, fatal, not closed, shrunk below half when over 2000 bytes).
- `d5b_pages_check( callable $change ): array` runs a before round, `$change()`, an after round, and returns `{ before, after, problems, unavailable }`; `unavailable` true when every before page failed to fetch (then `$change()` still runs and `after` is empty).
- `d5b_keep_copy( string $kind, string $dir_name, int $row_id ): array|WP_Error` copies `WP_PLUGIN_DIR/<dir>` or the theme root `/<dir>` (or a single plugin file) to `<store>/<row id>-<32 hex>/<kind>/<dir_name>/` with `copy_dir()`, returns `{ path, bytes, files }`; errors `copy_too_big` (over 536870912 bytes, measured before copying), `store_full` (`d5b_history_store_bytes()` + size over 2147483648), `copy_failed`.
- `d5b_history_store_bytes(): int` sums the store; `d5b_history_files_remove` removes nested folders (never following symlinks, only under the row's own folder).
- `d5b_maint_self( string $plugin_file ): bool`; `d5b_human_check(): string` (the fixed sentence, verbatim from the spec's "human check" section); `d5b_maint_rate( string $key, int $limit, int $window_s ): bool` (true when allowed, counts the attempt).

- [ ] **Step 1: Write the failing tests:**
  - `watched pages: home + 5 pages + 1 post, at most 7, cache-buster present`
  - `round: a page answering 500, a fatal, a cut-off page, a skipped page past the budget (fake clock)`
  - `compare: each rule from scripts/site-care/site-updates-test.js ported (bad-before not blamed; shrink below half only over 2000 bytes)`
  - `check: before all failed -> unavailable true, change still ran, after empty`
  - `keep_copy: a plugin whose folder differs from its slug copies the folder; a single-file plugin copies the file; over cap -> copy_too_big and nothing written; store full -> store_full; copy failure -> copy_failed; bytes and files counted`
  - `files_remove: a nested <kind>/<slug>/sub/file is removed; a symlink inside is unlinked, never followed (target untouched)`
  - `self: divi5-builder/divi5-builder.php and each legacy file true; others false`
  - `rate: limit N in window allows N then refuses; a new window allows again`
